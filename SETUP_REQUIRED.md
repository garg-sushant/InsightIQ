# Setup Required

Everything in this repository runs locally with **zero external accounts**:
`docker compose up` + the seed script gives you a fully working product,
including AI-narrative sections generated by the built-in offline analyst
(`MockProvider`). Nothing below is required to run, demo, or develop InsightIQ.

These are the external services you'd set up to go from "demo" to "production
with live AI and a public URL."

---

## 1. xAI Grok API key (optional — enables live AI narrative)

**Why:** Powers `GrokProvider`, which writes the executive summary, root-cause
analysis, recommendations and risk narrative from real language-model output
instead of the built-in offline analyst.

**Without it:** Everything works. `AI_PROVIDER=auto` automatically falls back
to `MockProvider`, which generates real (not lorem-ipsum) narrative from your
actual computed metrics using templates, and labels it clearly as offline
output in the UI and in exported reports.

**Steps:**
1. Go to https://console.x.ai and create an account.
2. Add a payment method (pay-as-you-go; no free tier as of writing).
3. Create an API key under API Keys.
4. Set `GROK_API_KEY=<your key>` in `.env`.
5. Restart the backend (`docker compose restart backend`).

**Env var:** `GROK_API_KEY` (also see `GROK_MODEL`, `GROK_BASE_URL` if xAI
changes their model lineup or endpoint).

**Paid:** Yes, pay-as-you-go.

---

## 2. Neon Postgres (production deploy only)

**Why:** `docker-compose.yml` runs Postgres locally for you. In production
(Render backend), you need a managed, internet-reachable Postgres instance.

**Without it:** Local development is unaffected — Postgres runs in Docker.
Only needed when deploying the backend to Render.

**Steps:**
1. Go to https://neon.tech and create a free account.
2. Create a project and database (free tier is sufficient for a demo deploy).
3. Copy the pooled connection string.
4. Rewrite it to use the async driver: replace `postgresql://` with
   `postgresql+asyncpg://` and append `?ssl=require`.
5. Set it as `DATABASE_URL` in the Render service environment.
6. Run migrations once: `alembic upgrade head` (the Render start command
   already does this on every deploy — see `render.yaml`).

**Env var:** `DATABASE_URL`

**Paid:** Free tier available; upgrade for production traffic/storage.

---

## 3. Render (backend hosting)

**Why:** Hosts the FastAPI backend as a public HTTPS service.

**Without it:** Run the backend locally via `docker compose up` — everything
works identically, just not internet-reachable.

**Steps:**
1. Go to https://render.com and create an account.
2. Connect your GitHub repository (push this repo to GitHub first — this
   build deliberately did not add a git remote or push anywhere).
3. Render should detect `render.yaml` and offer to create the blueprint. If
   not, create a new Web Service manually pointing at `backend/Dockerfile`.
4. Set the environment variables marked `sync: false` in `render.yaml`:
   `DATABASE_URL` (from Neon, step 2), `CORS_ORIGINS` (your Vercel URL),
   `GROK_API_KEY` (optional, from step 1).
5. Deploy. The health check is `GET /health`.

**Env vars:** see `render.yaml` — `DATABASE_URL`, `CORS_ORIGINS`, `GROK_API_KEY`.

**Paid:** Starter plan is a low-cost paid tier; Render's free web services
spin down on idle, which is a poor fit for an API backend.

---

## 4. Vercel (frontend hosting)

**Why:** Hosts the Next.js frontend as a public HTTPS site.

**Without it:** Run the frontend locally via `docker compose up` or `npm run
dev` inside `frontend/` — fully functional against a local or remote backend.

**Steps:**
1. Go to https://vercel.com and create an account.
2. Import this repository, set the root directory to `frontend/`.
3. Set the environment variable `NEXT_PUBLIC_API_BASE_URL` to your Render
   backend's public URL (from step 3).
4. Deploy.

**Env var:** `NEXT_PUBLIC_API_BASE_URL`

**Paid:** Free tier is sufficient for a demo deployment.

## Summary table

| # | Service | Required for | Env var(s) | Paid? |
|---|---------|--------------|------------|-------|
| 1 | xAI Grok | Live AI narrative (vs. offline analyst) | `GROK_API_KEY` | Yes |
| 2 | Neon Postgres | Production database | `DATABASE_URL` | Free tier OK |
| 3 | Render | Public backend hosting | `DATABASE_URL`, `CORS_ORIGINS`, `GROK_API_KEY` | Paid starter tier |
| 4 | Vercel | Public frontend hosting | `NEXT_PUBLIC_API_BASE_URL` | Free tier OK |

Nothing in this list blocks local development, testing, or a full offline
demo. `.env.example` at the repo root documents every environment variable
InsightIQ reads, with a working default for each one.
